# ilpacco.ru — маркетплейс Италия → Россия

Итальянские продавцы, покупатели в России, доставка посылками через хаб в Милане.
Здесь работающий MVP всего пути: каталог и комплаенс, цена «под ключ», оформление с картой пунктов выдачи,
оплата, продавец, хаб в Милане с фото, таможня, выдача по коду, споры, выплаты продавцам с документами,
уведомления по СМС и почте, личный кабинет покупателя. Бизнес-логика соответствует бизнес-плану и ТЗ (модель v2: одна посылка на заказ,
наземная доставка по умолчанию, тариф «себестоимость + 25 %»).

Публичный адрес — **ilpacco.ru**. Внутренние идентификаторы (папка `pacco/`, realm Keycloak## Что внутри

| Часть | Технологии | Папка |
| --- | --- | --- |
| Бэкенд | Java 25, Spring Boot 4.1, Spring Modulith 2.1, JPA + Flyway (V1–V5), Spring Security (JWT), Spring Mail | `backend/` |
| Витрина и кабинеты | Next.js 16, React 19, TypeScript, Leaflet (карта ПВЗ), keycloak-js | `web/` |
| Данные | PostgreSQL 17 (каталог, заказы, фото, выплаты, журнал уведомлений), Redis 7 (корзины) | `docker-compose.yml` |
| Вход | Keycloak 26, realm `pacco`, своя тема входа `ilpacco`; покупатели регистрируются сами | `infra/keycloak/`, `infra/keycloak-theme/` |
| Почта в тестовом стенде | Mailpit — ловит все письма, UI на `127.0.0.1:8025` | `docker-compose.yml` |
| Прокси и HTTPS | Caddy 2 — сертификат Let's Encrypt получает сам | `infra/Caddyfile` |
| CI/CD | GitHub Actions: тесты, сборка, запуск стека, smoke и браузерные проверки, образы в GHCR, релизы по тегу, деплой по SSH | `../.github/workflows/` |

### Модули бэкенда

Каждый пакет первого уровня — модуль Spring Modulith; `ModularityTest` проверяет границы.

| Модуль | Что делает |
| --- | --- |
| `compliance` | Правила: 290 € за единицу (санкции ЕС), продэмбарго РФ, алкоголь, аэрозоли; при смене правил каталог перепроверяется |
| `catalog` | Товары, модерация карточек продавцов |
| `pricing` | Цена «под ключ»: курс + буфер, доставка, пошлина ЕАЭС, сценарий НДС |
| `cart` | Корзины в Redis |
| `sellers` | Заявки продавцов и одобрение |
| `orders` | Оформление и оплата; путь продавец → хаб → таможня → ПВЗ → выдача; отмены, споры, фото, история событий, реестры выплат, очередь уведомлений (outbox) |
| `buyers` | Профиль покупателя: данные для оформления, ПВЗ по умолчанию, каналы уведомлений |
| `delivery` | Справочник пунктов выдачи с координатами |
| `notifications` | Рассылка СМС (SMS.ru) и писем (SMTP) по событиям заказа, журнал отправок |

Документация API: `/swagger-ui.html`.

## Локальный запуск

Нужен Docker с Compose v2.

```bash
cd pacco
cp .env.example .env
# в .env: PUBLIC_URL=http://localhost и SITE_ADDRESS=:80
docker compose up -d --build
./infra/smoke.sh          # весь путь: заказ → оплата → продавец → хаб с фото → таможня → ПВЗ → выдача → спор → выплата → письма
```

Сайт: http://localhost · Keycloak: http://localhost/auth (консоль — `admin` / `KEYCLOAK_ADMIN_PASSWORD`) ·
письма покупателям: http://127.0.0.1:8025 (Mailpit).

Или без сборки — готовые образы последнего релиза:

```bash
TAG=ilpacco-v$(cat VERSION) docker compose pull backend web && TAG=ilpacco-v$(cat VERSION) docker compose up -d --no-build
```

Разработка по частям:

```bash
docker compose up -d postgres redis keycloak
cd backend && mvn spring-boot:run          # http://localhost:8080
cd web && npm install && npm run dev       # http://localhost:3000, /api проксируется на 8080
cd backend && mvn verify                   # тесты; интеграционные требуют postgres и redis
```

## Деплой на сервер

Подойдёт VPS с Ubuntu 24.04, 2 vCPU и 4 ГБ RAM, например в Yandex Cloud или Selectel.

1. Установите Docker: `curl -fsSL https://get.docker.com | sh`.
2. Направьте A-запись домена на IP сервера и откройте порты 80 и 443.
3. Подготовьте каталог и настройки:
   ```bash
   sudo mkdir -p /opt/pacco && sudo chown $USER /opt/pacco && cd /opt/pacco
   git clone https://github.com/lisiks-dot/krymmedia.git src && cp -r src/pacco/* src/pacco/.env.example .
   cp .env.example .env && nano .env     # PUBLIC_URL, SITE_ADDRESS, пароли
   ```
4. Запустите — из готовых образов CI или со сборкой на сервере:
   ```bash
   docker compose pull && docker compose up -d     # образы ghcr.io/lisiks-dot/pacco-*
   # или
   docker compose up -d --build
   ```
5. Проверьте: `BASE=https://ваш-домен ./infra/smoke.sh`.

Дальше обновления выкатывает workflow **«ilpacco · деплой на сервер»** (Actions → Run workflow).
Ему нужны секреты репозитория `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `DEPLOY_PUBLIC_URL`
и, если пакеты GHCR приватные, `GHCR_TOKEN` с правом `read:packages`.

## Уведомления

| Канал | Переменные `.env` | Без настройки |
| --- | --- | --- |
| Почта | `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM` | Письма ловит Mailpit на сервере, покупателям не уходят |
| СМС | `SMS_RU_API_ID`, `SMS_SENDER` (ключ из кабинета SMS.ru) | СМС только пишутся в журнал (`/admin/notifications`, статус «только журнал») |

Ссылки в сообщениях строятся от `PUBLIC_URL`.

## Перед запуском с реальными покупателями

- Сменить пароли пользователей `admin` и `support` в Keycloak (в импорте realm стоит `change-me-now`) и закрыть `/auth/admin` по IP.
- Подключить эквайринг МИР и СБП вместо `StubPaymentGateway` и платёжного агента для выплат продавцам.
- Хранить паспорт и ИНН зашифрованными у таможенного представителя (сейчас сохраняется только маска паспорта).
- Обновлять курс ЦБ задачей по расписанию (сейчас — переменная `RUB_PER_EUR`).
- Подключить OpenSearch для поиска с морфологией и S3 для фото товаров, когда каталог вырастет.
- Подключить SMS.ru и боевой SMTP; короткие ссылки в СМС.
- Заполнить реквизиты ООО в документах выплат (`web/components/PayoutDocs.tsx`) и проверить налоговые формулировки с бухгалтером.
- Заменить демо-справочник ПВЗ данными СДЭК/Boxberry/Почты, карту — Яндекс Картами или 2ГИС.
- Перенести фото в S3-совместимое хранилище при росте объёма.
- Realm Keycloak импортируется только при первом запуске. На уже развёрнутом сервере роли `ops`/`finance`, пользователей, тему входа `ilpacco` и саморегистрацию нужно включить в консоли Keycloak вручную.
